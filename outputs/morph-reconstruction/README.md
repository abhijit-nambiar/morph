# Morph reconstruction experiment

A local command-line research baseline: group photos by simple illumination/color features, produce an edited target with several deterministic controls, recover controls by bounded numerical fitting, and replay the recovered recipe on the scene. No API or model weights. The fitting model is numerical optimization, not a trained neural network. Scene assignments are an approximate starting point and can be edited in the JSON before rendering.

Requires Python 3, NumPy and Pillow (`python3 -m pip install numpy Pillow`). From this folder:

```bash
python3 morph.py group /Users/abhijitnambiar/Downloads/Morph/originals --scenes 4 --out groups.json
python3 morph.py group /Users/abhijitnambiar/Downloads/Morph/originals --method chronological --gap-minutes 5 --out groups-by-time.json
python3 review_groups.py groups.json --source /Users/abhijitnambiar/Downloads/Morph/originals --out group-review
python3 morph.py album groups.json --preset warm --target-engine pillow --out album
python3 morph.py evaluate /Users/abhijitnambiar/Downloads/Morph/originals /Users/abhijitnambiar/Downloads/Morph/edits --limit 10 --out real-evaluation
python3 evaluate_transfer.py groups.json /Users/abhijitnambiar/Downloads/Morph/edits --out real-transfer
```

Each scene contains a synthetic target, recovered preview, fit.json with fitted parameters, and full-resolution exports. `--target-engine pillow` makes targets with independent Pillow brightness, contrast and color operations, while Morph fits and renders the exports. `--target-engine morph` (the default) makes targets with the same renderer as the fitter, so it measures inverse fitting under favorable conditions. Custom JSON recipes work with the Morph target engine; Pillow uses its own fixed presets. Full-size results require memory; processing is sequential.

The default `target.jpg`, `reconstruction.jpg`, and `applied-preview.jpg` are small fitting-resolution previews, not full-resolution images. Individual photos in each `exports/` folder are full resolution. Add `--full-res-reference` to the `album` command to also save full-resolution `target-full.jpg`, `reconstruction-full.jpg`, and `applied-full.jpg` for each representative. This option supports `morph`, `pillow-soft`, `spatial-soft`, `gaussian-soft`, and supplied targets; it does not support the other Pillow target engines. The settings are still fitted at `--size`; these extra images are rendered from the original-resolution sources. Full-resolution target generation and preview generation operate at different resolutions and may differ slightly after resizing and JPEG encoding.

Use `album ... --preview-only --full-res-reference --out preview` to fit and review representatives before batch export. Add `--preview-samples 3` to render up to three full-resolution photos per scene in `samples/`, with per-sample clipping diagnostics; the first is the representative and the others are selected for appearance diversity. Selection is heuristic, not semantic scene recognition. Preview mode does not render or assess the remaining album photos, and `report.json` distinguishes `sample_count` from `export_count`. Once the looks and groupings are reviewed, `python3 morph.py apply groups.json preview --out album-output` renders all originals using the saved fits and produces per-photo diagnostics.

For a numeric transfer check, add `--evaluate-transfer`: each rendered photo is compared at fitting resolution with the deterministic target independently created for that photo, or with its supplied same-name target. `review.json` records source-to-target and output-to-target RMSE; `report.json` counts non-representative photos evaluated and those whose output has higher error than the source. Missing or differently sized supplied targets are marked unavailable. Supplied same-size targets may still be misaligned or have different intended edits. These metrics are computed before JPEG export, do not establish visual quality, and a reduced `--strength` intentionally moves the output away from the original target. In preview mode, only selected samples are checked.

`resolution_experiment.py groups.json example-target-settings.json --out resolution-experiment.json --groups-limit 9` compares fitting at 320, 640, and 1024 pixels on one representative per group against a fixed sample of original-resolution pixels. On the current album and one soft target, error differed little across those fit sizes; that does not establish full-image, JPEG, or unseen-album quality. The reported fit time excludes image loading and target creation.

`detail_fidelity.py groups.json --out detail-fidelity.json` checks full-resolution neutral rendering and JPEG re-encoding on representative images. It samples pixels from the original and decoded output; it does not evaluate perceptual sharpness, non-neutral edits, or camera RAW quality. JPEG export is lossy even when the editing settings are neutral.

`group`, `target`, `fit`, `album`, `apply`, and `evaluate` refuse to overwrite their input files and refuse to replace existing planned outputs unless `--overwrite` is supplied. `--overwrite` still cannot overwrite an input. It replaces only planned output files and does not delete stale files from earlier runs, so a new output directory is safest for each run.

`--target-engine pillow-selective` generates a more complex target using Pillow global edits plus hue-range saturation adjustments in HSV. It is an independent deterministic composite, not an AI-generated look; it uses the fixed `--preset` vocabulary. For example: `python3 morph.py album groups.json --target-engine pillow-selective --renderer selective --solver gauss-newton --preset warm --out album-complex`. The `complex-target-benchmark` report compares global, selective, and bounded renderers on representative fits and held-out photos from the same album.

`--target-engine pillow-soft` is a gentler independent target: bounded per-channel tone lookup tables and HSV hue-range saturation adjustments. For example: `python3 morph.py album groups.json --target-engine pillow-soft --renderer gamut --solver gauss-newton --preset warm --out album-soft`. On the available album its targets and bounded-renderer reconstructions triggered fewer near-limit flags than the stronger Pillow composite; inspect `soft-target-benchmark` for the actual images and metrics. The look is subtler, and neither the heuristic nor low pixel error confirms photographic quality.

`benchmark_random_targets.py groups.json --out random-target-benchmark` evaluates random combinations of independent soft-target settings. `joint_fit_experiment.py groups.json random-target-benchmark/report.json --out joint-fit-experiment.json` compares fitting one representative against up to three diverse representatives, keeping the same held-out photos. In one album this joint fit improved 34 of 68 cases but did not improve mean error, so it remains experimental rather than an album default.

`multi_real_experiment.py groups.json EDITS --out multi-real-experiment` compares one versus up to three diverse same-size original/human-edit anchors, holding out other same-size photos in each proposed scene. Its comparison sheets are low-resolution review previews, not album exports. On this dataset mean error improved slightly but median error worsened; the result is mixed, groups are unvalidated, and same-size pairs may still be misaligned.

`album_joint_experiment.py groups.json example-target-settings.json --out album-joint-experiment.json` compares a single recipe fitted from representatives across the whole album with separate per-scene fits. All targets share the same independent deterministic settings, and evaluation uses other photos. On this album the shared recipe had lower pixel error for 6 of 25 held-out photos; this does not measure subjective album consistency and has not been tested on an unseen album.

For real matched pairs, `real_album_baseline.py` compares one shared album recipe and separate scene recipes on the same held-out photos. `anchored_scene_experiment.py` then tests regularizing each scene toward that shared recipe. The current single-album experiment showed mixed results and none of the tested penalties improved mean transfer error over unregularized scene fits. Penalties were examined on the evaluation data; this is not an independent selection or a measure of perceived consistency.

Use `benchmark_random_targets.py groups.json --scale 1.75 --out strong-target-benchmark` to sample stronger control combinations (the default scale is 1; the maximum is 2). Settings are bounded and nonmonotonic target curves are rejected. The provided strong-target report covers 36 looks and 68 held-out photo/look combinations from this album, not an unseen album. Near-limit flags are heuristic and do not replace visual review.

You can set the independent target's controls with `--target-settings example-target-settings.json` instead of a preset. Supported keys are `tone_exposure`, `tone_contrast`, `tone_shadows`, `tone_highlights`, `tone_temperature`, `cool_saturation`, and `warm_saturation`, each between -0.5 and 0.5; omitted keys are zero. Tone curves must also be bounded and monotonic. The chosen target settings are recorded separately in each scene's `fit.json`. They describe Pillow lookup-table and HSV operations, not the renderer's sliders; comparing their numeric values directly to `fitted_recipe` is not meaningful. Evaluate the reconstructed image and transfer instead.

`--prompt` is an optional no-API-key interface for `pillow-soft`, `spatial-soft`, and `gaussian-soft` targets, with a small explicit vocabulary rather than general natural-language understanding. For example: `python3 morph.py album groups.json --target-engine pillow-soft --prompt 'warm, slightly soft contrast and lift shadows' --renderer polynomial --solver least-squares --regularization .001 --out prompted-album`. Run `python3 morph.py prompt-help` for all supported phrases. Separate phrases with commas, semicolons, or `and`; `slightly` and `strongly` scale an individual phrase. Unsupported, repeated, or conflicting phrases are rejected instead of silently ignored. Prompt and interpreted controls are recorded in the output. `--prompt` cannot be combined with `--target-settings`, `--targets`, or `--recipe`. This is a deterministic stub for a future generative target proposal, not a language model.

`prompt_semantics.py groups.json --out prompt-semantics.json` checks whether each supported phrase moves a chosen numeric metric in the requested direction for a representative target and one different photo receiving the fitted mapping. This is only a directional sanity check; it does not establish magnitude, natural-language understanding, artistic quality, or generalization to unseen albums.

New target and album exports preserve standard source EXIF metadata where Pillow can read it, including capture time and potentially location. Orientation is normalized to the already-oriented pixels, and exports carry an sRGB ICC profile. Other metadata formats such as XMP/IPTC are not preserved. The older `full-album-test` run began before EXIF preservation was added and does not retain EXIF.

Each album export includes `review.json`, with sampled near-white (any channel at or above 254/255) and near-black (all channels at or below 1/255) pixel fractions before and after editing, measured before output encoding. An increase of more than one percentage point is flagged for review. The threshold is heuristic: legitimate bright or dark regions can be flagged, and edits with no flag can still be poor. It does not recover clipped detail or measure color accuracy.

Run `python3 review_album.py album/review.json --out album-review` to create side-by-side source/export contact sheets. The generated `index.json` lists the pages and number of photos.

The `album` command accepts `--strength` from 0 to 1 (default 1), scaling the fitted controls toward neutral for export. `fit.json` stores both the fitted recipe and the applied recipe; `reconstruction.jpg` always shows the full fit, and `applied-preview.jpg` shows the export strength. Reducing strength changes the requested look and does not guarantee an absence of clipping. JPEG output at zero strength still has encoding differences.

To reuse saved scene fits without re-optimizing, run `python3 morph.py apply groups.json PREVIOUS_ALBUM_OUTPUT --out rerendered`. It reads each scene's `fit.json`, checks that its representative matches the groups file, uses the recorded renderer and strength, and renders from the originals. Edit `fitted_recipe` in a copy of the scene fit file to change sliders, or pass `--strength` to override saved strengths. The output contains each `applied.json`, exports, and a new clipping-review report. New fits are saved at full numeric precision; older fits saved to six decimals may replay with tiny pixel differences.

New scene fits also record each source path and SHA-256 checksum. `apply` checks scene membership and file contents before rendering; if either changed, re-fit or explicitly pass `--allow-changed-inputs` to reuse the look anyway. A changed representative is always rejected. Older fits without checksums remain usable but emit a warning and are marked `legacy-unverified` in the output. Checksums identify file contents, not whether the photographic look is appropriate.

For deliberate adjustments after reviewing a scene or album, supply `--corrections corrections.json` to `apply`. The optional `album` object applies to every photo, `scenes` maps scene IDs to corrections, and `photos` maps scene IDs to filename/correction pairs; see `example-corrections.json`. Each correction uses the control names and bounds of that scene's saved renderer, except polynomial, spatial and grid mappings use the gamut renderer for corrections. The deterministic order is photo correction, fitted scene look, scene correction, then album correction. These are composed image operations, not added slider values; `--strength` scales only the fitted look. Applied corrections and their renderer are recorded in each scene's `applied.json`. Unknown scenes/photos and invalid controls are rejected. This is manual control; it does not automatically normalize exposure or guarantee a consistent look.

`clipping_budget_experiment.py` tests reducing strength separately for each photo until a thumbnail meets a chosen near-limit-pixel budget. It is experimental, is not part of the exporter, and does not guarantee the budget at full resolution or after JPEG encoding. On the supplied album, a one-percentage-point budget reduced median strength to 0.20 and chose zero for eight photos, potentially undermining the look and scene coherence. See `clipping-experiment/report.json` before considering this heuristic.

`gamut_renderer.py` is an experimental alternative that maps tone through bounded curves and limits saturation to the display gamut. Use `--renderer gamut --solver gauss-newton` with `fit` or `album`. The same numeric controls yield different appearances in different renderers, so save and replay recipes with the same renderer. `compare_gamut.py groups.json example-selective.json --out gamut-experiment` compares the near-limit heuristic across the source album; this is not an equal-look comparison and does not prove detail preservation. Its reconstruction experiment (`gamut-real-transfer.json`) was slightly worse on average than the existing global model on this one dataset; no unseen-album validation has been done.

The experimental `--renderer polynomial --solver least-squares --regularization .001` fits a deterministic nonlinear RGB color mapping rather than sliders. For example: `python3 morph.py album groups.json --target-engine pillow-soft --renderer polynomial --solver least-squares --regularization .001 --out poly-album`. It is a global per-pixel color mapping; it cannot alter geometry or apply spatial edits, and it can clip or overfit. It uses a direct linear solve, so `--iterations` does not affect it. `fit.json` records its feature order and weights; `apply` can replay and scale the mapping and compose corrections using the gamut renderer. On the supplied real pairs it reduced held-out error for 30 of 38 photos relative to the bounded renderer, while on the randomized synthetic benchmark it reduced error for 23 of 68 and was slightly worse on average. See `poly-real-comparison.json` and `poly-synthetic-comparison.json`; results use one album and differ in solver sample sizes.

`--renderer spatial --solver least-squares --regularization .0001` is an experimental global color map plus fixed center-weighted local light adjustment. For an independent deterministic test target, use `--target-engine spatial-soft --target-local-light .3` (range -0.5 to 0.5), optionally with `--prompt` or `--target-settings`. For example, `python3 morph.py album groups.json --target-engine spatial-soft --target-local-light .3 --prompt 'warm and lift shadows' --renderer spatial --solver least-squares --regularization .0001 --preview-only --preview-samples 2 --evaluate-transfer --out spatial-preview`. The saved mapping can be replayed with `apply`; correction layers use the gamut renderer. Full-resolution rendering uses image-wide coordinates across tiles, and tests compare tiled and whole-image output. On synthetic targets with that same fixed mask, it fit better than a global-only map on 34 of 34 held-out photo/look pairs; the no-local-adjustment baseline was similar. The center mask is frame-relative, not subject-aware, and may not transfer well when composition changes. Real local edits, unseen albums, and photographic quality are not yet validated.

`python3 spatial_real_compare.py gamut-real-transfer.json EDITS --out spatial-real-comparison.json` compares polynomial and spatial models on the same real representative pairs, using the same sampled pixels and regularization, and evaluates the same 38 held-out photos in eight proposed chronological scenes. With regularization 0.001 and fitting size 256, the spatial mapping had lower pixel RMSE on 30 of 38; mean RMSE was 0.06846 versus 0.06897 for polynomial. Both improved over the unedited source on 33 photos. These groups and alignments are not independently verified, individual edits may have different intentions, and the result is from one album. It does not demonstrate recovery of a real localized edit or establish visual quality.

For a deterministic off-center test target, use `--target-engine gaussian-soft --prompt 'warm and lift shadows' --target-local-light .3 --target-light-center .2 .3 --target-light-radius .18 .23 --renderer grid --solver least-squares --regularization .0001`. Center and radius are fractions of frame width and height (center range 0–1; radius range 0.03–1). The target combines Pillow color/tone adjustments with a smooth Gaussian light region; its settings are saved in `fit.json`. The mask is fixed to image coordinates and does not follow subjects. `--full-res-reference` and `--evaluate-transfer` work for this target. With `gaussian-soft`, a prompt can also include one frame-relative phrase such as `brighten upper left`, `slightly darken center`, or `strongly brighten lower right`. Run `prompt-help` for supported region names. A local phrase cannot be combined with an explicit local strength or center; a radius may still be supplied. The parser does not recognize subjects or arbitrary directions.

`offcenter_light_experiment.py` tests the centered mapping against off-center Gaussian targets; the centered and global models had similar mean errors across four held-out cases, indicating that the centered basis does not reliably represent those edits. The research-only `grid_light_experiment.py` fits nine smooth frame-relative lighting regions instead. For 68 held-out synthetic photo/look cases with off-center adjustments, grid error was lower than both simpler mappings in all 68; for 34 no-local baseline cases it was slightly worse on average than either. `grid_real_compare.py` tested the same basis on 38 real held-out pairs: its error was lower than both simpler mappings on 34, with mean RMSE 0.06667 versus 0.06846 for centered. These are exploratory tests on one album, use spatial shapes related to the synthetic targets, and do not establish visual quality or subject tracking. The grid model is available with `--renderer grid --solver least-squares --regularization .0001`, including preview and replay. It remains experimental: inspect for clipping and overfitting before batch export. Corrections use the gamut renderer.

For a saved grid fit, `python3 morph.py apply groups.json FITS --local-strength 0.5 --preview-samples 3 --out reduced-local-preview` scales only its local-light coefficients between 0 and 1; `--strength` still scales the entire mapping first. Omit `--local-strength` to preserve the full local contribution. The value is recorded in `applied.json`. To set a different value per scene, add `"local_strengths": {"scene-01": 0.5, "scene-02": 0.0}` to the corrections JSON; these values override `--local-strength` for those scenes, while unspecified grid scenes use the command-line value or 1.0. Unknown scenes, non-grid scenes with overrides, and values outside 0–1 are rejected before rendering. This option requires every scene fit in the batch to use the grid renderer. The global and local coefficients were fitted jointly, so zero local strength does not reproduce a separately fitted global-only model. Review the full-resolution samples before applying the choice to a whole album.

For a thumbnail comparison at local strengths 0, 0.5 and 1, run `python3 review_local_light.py build groups.json FITS --out local-review`. Enter one value from 0–1 per reviewed scene in `local-review/decisions.csv`, then run `python3 review_local_light.py compile local-review/decisions.csv --out local-corrections.json`. Blank scenes are omitted; `apply --corrections local-corrections.json` therefore uses its usual default for those scenes. The comparison shows only selected photos and does not include other correction layers or check checksums; `apply` validates source checksums where available. If combining with other corrections, merge the `local_strengths` object into your existing corrections JSON. Export full-resolution samples with `apply --preview-samples 3` before the whole album.

`moving_light_experiment.py` tests a limitation of frame-relative grid edits: a synthetic light region is shifted horizontally on each held-out photo while the fitted mapping stays fixed. With no shift, grid error was lower than global in 34 of 34 photo/look cases; with a shift of 30% of frame width, it was lower in 0 of 34. Mean RMSE at that shift was 0.02041 for grid and 0.01656 for global. The target's movement is prescribed, not detected; the masks resemble the grid basis, and the evaluation uses a single album. This does not quantify real subject movement or photographic quality, but it demonstrates why the same local edit can miss its intended area when compositions change. Review scene samples, particularly when subjects move, and consider a global renderer for such groups.

`detect_faces.swift` is an optional macOS Vision detector experiment included with the starter package. Compile it with `swiftc -module-cache-path CACHE_DIR detect_faces.swift -o DETECTOR`, then run the detector with image paths to obtain normalized oriented face boxes as JSON. macOS system image services failed inside this sandbox but worked outside it with CPU-only inference; the option used by the experiment is deprecated by macOS and portability is untested. `face_light_experiment.py` uses those boxes to build a smooth face-relative mask for both a synthetic target and its fitted model; this makes the test favorable and does not evaluate mask inference or human-edited faces. In one scene, with a positive synthetic face light, the face-relative mapping had lower held-out RMSE than frame-fixed grid on 11 of 11 photos (0.00552 versus 0.00802 mean); with no local light the means were similar. Detections have not been comprehensively validated, masks extend beyond faces, and no unseen album or aesthetic quality assessment has been performed. Review the detection thumbnails in `face-light-experiment/`; the experiment is not integrated into album export.

`detect_faces_regions.swift` is an optional second detector pass that analyzes overlapping regions without modifying photo geometry. On the four full-album photos with no first-pass detection it returned 6, 6, 15 and 15 boxes, although visual inspection suggests some people remain missed. `merge_face_detections.py` replaces only empty detections and verifies source checksums; see `face-regions-review/` for thumbnail inspection. Accuracy and false positives have not been systematically evaluated.

`face_independent_experiment.py face-split-groups.json face-detection-real-splits.json example-target-settings.json --out face-independent-multiscene.json` tests 38 held-out photos over eight proposed scenes with synthetic face edits whose elliptical feather differs from the model's Gaussian mask. At both ±0.3 local-light strengths, face-relative and hybrid mappings each reduced pixel error compared with grid on 38 of 38 cases; with no local adjustment the face-only mean was slightly worse and the hybrid mean was slightly better. The target and model both use the same detected face boxes, so this is not a test of detection accuracy, person selection, real edit reconstruction, or unseen-album generalization. The model is still experimental and not integrated into export.

`face_full_preview.py` is a research-only full-resolution preview of the face-relative synthetic experiment. It requires a reviewed group file and externally detected face boxes, fits on one representative, and exports independent elliptical targets and recovered Gaussian-mask edits for the representative and one held-out photo. The original dimensions are preserved; fitting still occurs at reduced resolution. `test_face_full_preview.py` verifies tile coordinates against whole-image target and model rendering. Face boxes were not verified for correctness and both target and model depend on them; the mask includes surrounding pixels. The tool does not detect faces itself, replay saved fits across an album, or validate professional quality.

`face_scene_pipeline.py` is a separate experimental scene workflow. For example, `python3 face_scene_pipeline.py fit groups.json detections.json --scene scene-01 --prompt 'warm and brighten faces' --out face-fit` stores the fitted mapping, original file checksums, and detected boxes for every photo; `python3 face_scene_pipeline.py apply face-fit/fit.json --preview-samples 3 --out face-preview` produces up to three full-resolution scene samples. Omit `--preview-samples` to render the scene. Use `--targets EDITS` instead of `--prompt` to fit same-name, same-size representative edits; inspect alignment and intent because equal dimensions do not guarantee either. The target path and checksum are saved in the fit. The representative must have a detected face if any photo in its scene does. If the entire scene has zero detections, the fit uses only global color and flags the scene. Any photo with zero detections receives only the global mapping and is flagged in `report.json` for review, since zero detections may mean a missed face. Failed or missing detection records and changed source bytes are rejected before rendering. Use `python3 detect_scene_faces.py groups.json --detector DETECTOR --out detections.json` to attach source checksums to locally generated boxes; fitting rejects changed photos or unverified legacy boxes unless `--allow-unverified-detections` is explicitly provided. Checksums do not prove detections are correct; inspect the boxes. It also supports `fit-album` and `apply-album` for all reviewed groups, using the restricted offline prompt vocabulary, and does not detect or select individual people. The face mask affects nearby surroundings and has not been validated for professional editing. This experimental workflow is included in the starter package; it remains separate from the main album command.

For a thumbnail overview of face-album output, run `python3 review_face_album.py ALBUM_OUTPUT --out album-review`. `album-review/index.json` maps each original to its full-resolution export; the sheets themselves are previews. Photos without detected faces are flagged for inspection.

Face-scene exports record reduced-resolution, pre-JPEG clipping diagnostics in each scene report. `near_limit_flag` means near-black or near-white pixel fraction increased by more than one percentage point; `face_mapping_out_of_gamut_fraction` measures pixels outside the display range before the fitted mapping clamps them. These are sampled heuristics, not visual-quality verdicts, and may miss small damaged areas. For an older export, run `python3 audit_face_album.py FACE_ALBUM_FITS ALBUM_OUTPUT --out clipping-audit.json` to recompute them from the originals and stored corrections.

After a full face album export, run `python3 verify_face_album.py FACE_ALBUM_FITS ALBUM_OUTPUT --out verification.json` to check photo coverage, original checksums, decoded dimensions, and ICC/EXIF presence. It flags images without face detections and missing or unexpected outputs. It does not check image quality, correct detection, all metadata, or every processing artifact.

`python3 evaluate_face_transfer.py FACE_ALBUM_FITS FACE_ALBUM_OUTPUT --out transfer.json` checks rendered photos against their independently recomputed synthetic targets at fitting resolution. It excludes representatives from the held-out summary and applies the stored correction layers. The target and fitted model use the same detected face boxes, and the score is pre-JPEG pixel error, not a photographic-quality or human-edit score. Preview runs only evaluate their selected samples. The face one-command workflow writes `transfer-evaluation.json` automatically.

`audit_scene_consistency.py FACE_ALBUM_FITS ALBUM_OUTPUT --out scene-consistency.json` is a review-only brightness check. It compares Gaussian-weighted luminance around detected face boxes to the median within each scene and flags large log2 luminance ratios. At least three measured photos are needed per scene; previews may contain too few. The values are computed on reduced-resolution, gamma-encoded images, not calibrated camera exposure stops. Face boxes can miss people or include surroundings, and skin tone, composition and intent can legitimately differ. The output suggests photos to inspect and applies no correction. The face one-command workflow produces this report automatically.

To inspect a particular full-resolution photo in one fitted face scene, use `python3 face_scene_pipeline.py apply FIT/fit.json --preview-photo PHOTO_FILENAME --out photo-preview`. Repeat `--preview-photo` for more than one scene member. It cannot be combined with `--preview-samples`; invalid or duplicate filenames are rejected. Add `--corrections` to compare reviewed adjustments.

The face workflow also accepts `--corrections corrections.json` on `apply` and `apply-album`, using the same `album`, `scenes`, and `photos` structure shown above. Corrections use the gamut renderer and are composed in this order: photo correction, fitted face look, scene correction, album correction. Unknown scene or photo names are rejected before batch rendering. In preview mode, the representative and individually corrected photos are prioritized. These are manual adjustments, not automatic exposure normalization; inspect full-resolution samples.

For review-only metadata suggestions with a face album fit, run `python3 suggest_face_exposure.py FACE_ALBUM_FITS --out draft-face-corrections.json`, then `python3 review_face_exposure.py FACE_ALBUM_FITS draft-face-corrections.json.audit.json --out face-exposure-review`. The sheets are thumbnails showing original, fitted look, and suggestion; other correction layers are not shown. Enter `accept` or `reject` in the decisions CSV, then use `python3 review_exposure.py compile face-exposure-review/decisions.csv --out approved-face-corrections.json`. Blank decisions are excluded. Use that file with `face_scene_pipeline.py apply-album --corrections` and render full-resolution samples before the album. Merge the resulting `photos` object into other corrections if needed. The metadata heuristic is imperfect and has had mixed results on one album; suggestions are not automatically applied.

`face_real_compare.py` uses those detected face masks to fit the existing real representative/edit splits. Across 38 held-out photos, its face-relative mapping had lower pixel RMSE than the frame grid on 4 (mean 0.06888 versus 0.06667). `hybrid_face_real_compare.py` adds the face features to the grid and produced lower error than grid alone on 26 of 38, but mean error changed only from 0.066668 to 0.066636. Face boxes were returned for all 46 original images in these splits, but their correctness was not systematically checked; pair alignment, edit intent, scene grouping, photographic quality, and generalization are unverified. The hybrids remain experiments, not album export options.

`face_exposure_experiment.py` tests a bounded pre-look exposure change based on face-weighted luminance relative to the representative. On the 38 real held-out pairs it adjusted 26, improving pixel error on 13 and worsening it on 13; median error increased. A post-hoc check restricted to 16 cases where an independently computed camera-metadata suggestion agreed in direction improved 11 and worsened 5. This filter was selected after inspecting the data, and both methods can be affected by lighting, makeup, complexion, composition, and intent. It is not independent validation or an automatic normalization feature; no unseen album or photographic-quality review was done.

`grid_multi_anchor_experiment.py multi-real-experiment/report.json EDITS example-target-settings.json --out grid-multi-anchor-experiment.json` compares a single representative with an equally weighted joint fit on two or three representative pairs, using the existing predetermined splits and the same 23 held-out real photos. The joint fit reduced RMSE on 8 of 23 photos; its mean error fell from 0.05887 to 0.05728 while median error increased from 0.04459 to 0.05311. On the same held-out photos with an independent synthetic off-center look, it reduced error on 10 of 23, with nearly unchanged mean error. The result is mixed, so multi-anchor grid fitting is not enabled as a workflow default. All results come from one album; human edits may vary, same-size pairs may be misaligned, and the synthetic local shape is related to the grid basis.

For polynomial and grid exports, `review.json` additionally includes `polynomial_out_of_gamut_fraction` or `grid_out_of_gamut_fraction`: the spatially sampled fraction of pixels with at least one channel outside 0–1 before the mapping's clamp (after any per-photo correction, before later scene/album corrections). It is not the same as the near-limit flag and does not prove visible damage. `poly_mapping_audit.py poly-real-comparison.json --out poly-mapping-audit` additionally checks a synthetic RGB cube and held-out photos; the cube is not representative of a photograph's color distribution.

For a supplied target instead of a synthetic target, run `python3 morph.py album groups.json --targets EDITS_FOLDER --out album-from-edits`. That folder must contain a same-name, same-dimension image for every representative; it is up to the user to check alignment even when dimensions match. The fitted recipe from each representative is transferred to its group. The separate `evaluate_transfer.py` command fits one same-size edited pair per proposed group (falling back to the first eligible photo when the configured representative has no same-size target), evaluates other same-size pairs, and generates comparison sheets. It reports identity and transfer RMSE; neither verifies perceptual quality, intended scene consistency, or geometric alignment.

The transfer evaluator also accepts `--solver gauss-newton`. On this dataset's 38 same-size held-out pairs using chronological groups, Gauss–Newton had lower RMSE on 30 pairs than pattern search, with a small reduction in median RMSE. This comparison uses the same representatives but different optimizer pixel samples; it remains an in-sample, single-album experiment.

`python3 normalization_experiment.py real-transfer/report.json --out real-transfer/normalization.json` tests a bounded median-luminance adjustment against the same held-out pairs. It is an offline experiment, not part of album export: on the provided album it reduced error on 18 of 43 pairs but increased median error overall. Whole-image brightness can change because of composition rather than exposure, and no independent scene or alignment labels are available.

`metadata_normalization_experiment.py gamut-real-transfer.json EDITS --out metadata-normalization.json` tests a second offline approach: a bounded correction based on each photo's shutter time, ISO and aperture relative to the representative. It ignores scene-light changes, camera processing and photographer intent, so it is not enabled for export. In this album's 38 held-out pairs, the tested correction strengths improved 13, worsened 9 and left 16 effectively unchanged (using a 1e-6 RMSE tolerance); tuning was done on these same photos, not validated on an unseen album.

`python3 suggest_exposure.py groups.json ALBUM_FITS --out draft-corrections.json` creates **review-only** correction candidates based on that metadata. By default it proposes at most 0.25 exposure units, only for the same camera within 15 minutes of the representative and a 0.3–2 stop camera-settings difference. The model's exposure units are not calibrated camera stops. The companion `.audit.json` records proposals and skipped photos. It changes no images; inspect and edit/remove candidates before use. Preview some full-resolution examples with `python3 morph.py apply groups.json ALBUM_FITS --corrections draft-corrections.json --preview-samples 3 --out correction-preview`. Apply preview prioritizes the representative plus individually corrected photos; it assesses only those samples. This is a heuristic based on one album and may worsen results. It supports fits using the gamut, polynomial, spatial, or grid renderers (the latter three use gamut correction layers).

To review each proposed change before applying it, run `python3 review_exposure.py build groups.json ALBUM_FITS draft-corrections.json.audit.json --out exposure-review`. The contact sheets are thumbnails comparing original, scene look, and suggestion. Edit `exposure-review/decisions.csv`: put `accept` or `reject` in each decision cell (leave blank to exclude an unreviewed photo), then run `python3 review_exposure.py compile exposure-review/decisions.csv --out approved-corrections.json`. The result contains only `accept` decisions. You can inspect full-resolution sample outputs before rendering the album with `apply --preview-samples`; `apply` verifies saved source checksums where available. Building thumbnail sheets itself does not verify them.

Review each group contact sheet: the red frame marks its representative. Edit `groups.json` to move image paths between `photos` lists, split or rename groups, or change the representative. Each representative must appear in its group's photos. A photo may appear only once, filenames must be unique within a group, and group IDs may contain letters, digits, hyphens and underscores. Rerun `review_groups.py` after edits: its `index.json` lists unassigned images and assignments outside the supplied `--source` folder. Album export checks the group file for duplicate assignments, missing image files and invalid representatives, but does not itself know which images should have been assigned; check the review audit first.

The optional chronological grouping sorts by EXIF capture time and splits after a chosen time gap or camera model change; missing timestamps become individual groups. It chooses a representative near each group's average appearance. This keeps time-adjacent bursts together, but time alone does not verify that lighting or scene is consistent and camera clocks may be wrong. Five minutes is a heuristic, not a trained or validated threshold. `--scenes` is used only by appearance grouping; `--gap-minutes` by chronological and hybrid grouping.

`--method hybrid --gap-minutes 5 --approx-photos-per-group 8` first separates by capture time, then subdivides larger batches by basic color and exposure statistics. The requested group size is approximate, not a hard maximum. On the 30 matching held-out photos in the provided album it did not consistently outperform chronological grouping; this is a heuristic and not scene recognition. Review the contact sheets before use.

Other commands: `target ORIGINAL --preset soft --out target.jpg` creates a target and a JSON recipe; `fit ORIGINAL TARGET --out fitted` fits aligned image pairs. Use `--recipe recipe.json` on target or album for a custom object with any of: exposure (-1.5 to 1.5 stops), temperature (-0.4 to 0.4), tint (-0.3 to 0.3), contrast (-0.6 to 0.6), shadows/highlights (-0.5 to 0.5), saturation (-0.8 to 0.8). Zero is neutral. Operations are ordered, global, and applied per pixel; they cannot move or synthesize content. Inspect the code for exact definitions. A preset is a fixed composite, not free-text prompt interpretation.

`fit` and `album` accept `--iterations` (default 45). Increasing it gives the coordinate-search optimizer more chances to improve, at increased runtime; different controls may still have similar visual effects, so more iterations cannot guarantee recovery of the original slider values. `python3 parameter_recovery.py groups.json --out parameter-recovery.json` measures recovery of randomly sampled known recipes and transfer to another photo per group.

`fit` and `album` also accept `--solver gauss-newton` for an alternative damped numerical least-squares solver; the default `pattern` preserves the original method. On 24 moderate same-renderer synthetic cases, Gauss-Newton recovered the known controls more closely; on 36 held-out Pillow-generated photo/look combinations it reduced average transfer RMSE slightly. The two methods use different pixel samples, and neither result validates professional output or proves generalization to unseen albums. `solver-comparison.json` and `solver-comparison-pillow.json` contain the experiments.

`selective.py` is an experimental renderer adding `cool_saturation` and `warm_saturation` controls (each -0.7 to 0.7), derived from soft RGB masks. It preserves image geometry but is not a semantic sky or skin mask. Use `--renderer selective --solver gauss-newton` with `fit` or `album`; for example `python3 morph.py album groups.json --renderer selective --solver gauss-newton --recipe example-selective.json --out selective-album`. A recipe generated by one renderer must be replayed by that same renderer. `compare_selective.py chronological-transfer-gauss/report.json --out selective-comparison.json` compares it with the global renderer on held-out photos from the same album. On this set it improved RMSE slightly on average, but some parameters hit their limits; this can indicate insufficient information or overfitting.

The selective renderer accepts `--regularization` to penalize the two selective controls. A small penalty removed boundary hits and had a similar transfer error on this album, but the strength was inspected on the evaluation set and has not been selected or validated on unseen albums. See the `selective-regularized-*.json` reports. The solver records both pixel MSE and its penalized objective; these are not interchangeable.

Real-pair evaluation skips different dimensions; equal dimensions do not establish alignment, so inspect the pairs for crop, rotation, or retouching. JPEG recompression and different editors can limit reconstruction. Reported fit errors are on the same sampled pixels used by the optimizer and are not held-out accuracy. Correlated controls may yield different slider values for visually similar images; judge both parameters and images. The grouping uses color and lighting statistics, not capture time or semantic scene recognition; review groups manually. This is a research prototype, not validated professional editing, a RAW workflow, or a guarantee of consistent album aesthetics. It does not yet implement per-photo normalization, human review, or a general prompt interpreter.

Evaluation saves contact sheets labeled original / human edit / reconstruction, in addition to individual reconstructed previews and the JSON report. `--limit` counts fitted pairs, not skipped pairs. Increase it to 100 to check all 88 available pairs.

`python3 alignment_audit.py ORIGINALS EDITS --out alignment-audit.json` checks same-sized pairs for obvious shifts by comparing thumbnail gradients over small translations. It does not detect all crop, rotation, scaling, or local retouching; unflagged is not proof of pixel alignment. Differently sized pairs are reported separately and not aligned automatically. Thresholds are heuristic.

`python3 crop_match.py ORIGINAL TARGET --out crop-check` runs an experimental gradient-based crop search for a single pair and saves the estimated crop, target preview, and normalized crop coordinates. It searches scale and translation but not rotation or local warps. Scores are not calibrated and results must be inspected; the estimate is not automatically used for fitting or final export. It has been tested on a synthetic crop; the dataset-wide estimates have not been validated.

`python3 audit_crops.py ORIGINALS EDITS --out crop-audit` runs the same search on all differently sized pairs and produces review sheets and a JSON report. It proposes correspondences rather than proving registration; scores are uncalibrated, and a person must verify the visual matches before using them for evaluation.

`python3 evaluate_cropped.py crop-audit/report.json --out cropped-evaluation` runs a provisional fit on those estimated crops and produces comparison sheets. These scores use the same pixels that were fitted and inherit crop-matching uncertainty and resampling errors. The procedure does not use crops to export photos and should not be treated as a validated measure of reconstruction accuracy.

Run `python3 benchmark.py groups.json --out benchmark` to test three known looks on each representative and compare transfer on other photos. The benchmark uses the same renderer for target generation and fitting; it tests reconstruction and transfer under favorable conditions, not how well edits match human taste. The old red/blue controls were removed because they were exactly redundant with other channel multipliers; previous nine-control recipes are incompatible.

For a stronger cross-renderer check, run `python3 benchmark.py groups.json --engine pillow --out benchmark-pillow`. Pillow creates the targets with a different sequence of brightness, contrast, and color adjustments, plus channel gains; the fitter still uses the Morph renderer. The target recipe is not directly comparable to Morph slider values. Both benchmark modes use the same selected album; the grouping has not been independently validated.

`edit_scene_groups.py build groups.json --out assignments.csv` exports scene assignments to an editable CSV. Set each row’s scene and mark exactly one representative per scene with `yes`, then `edit_scene_groups.py compile groups.json assignments.csv --out reviewed-groups.json`. Compilation checks every original appears exactly once, scene IDs and representatives are valid, and records the source group checksum. Refit after editing groups. `groups-example-split.json` is an illustrative split of the original scene 02 into lawn and building groups, not a verified classification.

`evaluate_scene_split.py` compares the original scene 02 mapping with the illustrative lawn/building split against per-photo synthetic targets. Both representatives are excluded. On 11 held-out photos, the split reduced error on all five lawn photos; the six building photos were unchanged because their representative and fit stayed the same. This is one manually selected split and a common deterministic synthetic look, not evidence of better real-edit matching. The edited dataset has only two same-dimension lawn pairs and one same-dimension building pair in this split; the chosen building representative has different target dimensions, so the available pairs do not independently validate that side. See `scene-split-synthetic-evaluation.json` and `scene-split-real-eligibility.json`.

`face_album_workflow.py GROUPS --detections DETECTIONS --prompt "warm and brighten faces" --out RUN` chains detection review, per-scene fitting, full-resolution previews, review sheets and sampled clipping checks. Add `--full` for all photos and file verification, or `--detector DETECTOR` to create detections first. This is experimental: group and face-detection review remain necessary, and automated detection is not a quality guarantee. Failed runs leave partial output and a `run.json` status. `test_face_album_workflow.py` exercises preview, full export, and failure preflight.

`face_album_workflow.py --originals FOLDER` proposes chronological groups before the remaining workflow. It produces `groups.json` and thumbnail group sheets, but does not pause for review. Time-based groups are not verified scene recognition; inspect and correct them before depending on the album.

`album_workflow.py` is the unified prompt entry point. Global color/tone prompts use the gamut renderer without a face detector; frame-local phrases use the grid renderer; face-light phrases delegate to the face workflow and require local detections. It accepts a reviewed group JSON or `--originals` for unreviewed chronological groups; default output is a full-resolution sample preview, and `--full` renders and verifies the whole album. `test_album_workflow.py` checks all three routes and full-export integrity failures.
